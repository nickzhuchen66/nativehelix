# NativeHelix Agent Instructions

## Purpose

NativeHelix is a public AI-Native Skills and Capabilities Toolkit. Preserve the distinction between product intent, architecture, implementation, review, and final human authority.

## Starting a task

1. Read `README.md` and `00_Governance/PUBLIC_OPERATING_MODEL.md`.
2. Identify the human product owner and the requested outcome.
3. Before architecture or implementation, confirm the final artifact and user consumption path using the Outcome–Artifact Definition Gate.
4. Load only the Capability domains and Skills needed for the task.

## Evidence discipline

- Separate observed facts, external claims, inferences, and recommendations.
- Design does not equal implementation.
- Test success does not equal product effectiveness.
- Review does not grant write, release, spending, or production authority.
- Do not copy secrets, credentials, personal data, private project material, or unnecessary source content into outputs.

## Authority

- Product owners define users, value, scope, priority, and product acceptance.
- Architects define system boundaries, interfaces, state, permissions, resilience, and technical risk.
- Builders implement frozen product and technical inputs.
- Reviewers verify without redesigning the subject.
- Humans retain final authority for consequential external effects.
